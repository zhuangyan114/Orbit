## ARMGCC

### 什么是ARMGCC

ARMGCC是一类总称,我们要使用的是arm-none-eabi-gcc \
**arm-none-eabi-gcc** 是用于 ARM 裸机开发的开源交叉编译工具链，可将 C/C++ 程序编译为适用于 ARM Cortex-M 等微控制器的可执行代码。

### 下载 ARMGCC

1. 从 Arm 官方下载 GNU Arm Toolchain。

   [官方下载链接](arm-gnu-toolchain-15.2.rel1-mingw-w64-x86_64-arm-none-eabi.zip)

   下载 Windows 64 位版本，例如：

   > arm-gnu-toolchain-15.2.rel1-mingw-w64-x86_64-arm-none-eabi.zip

2. 也可以下载 xPack 发布的 ARM GCC。

    [github下载链接](https://github.com/xpack-dev-tools/arm-none-eabi-gcc-xpack/releases/tag/v15.2.1-1.1)

   xPack 对官方 Arm GNU Toolchain 进行了重新打包，包含相同的 `arm-none-eabi-gcc` 编译工具链，可直接用于 STM32 开发。

   例如：

   > xpack-arm-none-eabi-gcc-15.2.1-1.1-win32-x64.zip

### 安装ARMGCC

1. 把解压后的文件夹放到C盘根目录

2. 设置环境变量

    设置>系统>系统信息>高级系统设置>环境变量,找到系统变量里的Path,双击进入编辑环境变量>新建
    把刚刚移到C盘的文件夹的bin的文件目录粘贴进去
    如:
    > C:\xpack-arm-none-eabi-gcc-15.2.1-1.1\bin

3. 验证

    在PowerShell里输入 `arm-none-eabi-gcc --version` ,有显示版本号即可

## CMake

### 什么是CMake

CMake 是一个用于管理和生成编译工程的工具。它本身通常不负责直接编译代码，而是根据工程中的配置文件，生成对应编译工具能够识别的构建文件。

简单来说，CMake 就像一份“编译说明书”。我们在 `CMakeLists.txt` 中告诉它：

- 工程中有哪些源文件；
- 需要搜索哪些头文件目录；
- 需要链接哪些库文件；
- 使用哪一种编译器；
- 最终生成什么类型的文件。

CMake 读取这些配置后，可以生成不同平台和不同构建工具所需要的文件，例如 Makefile、Ninja 构建文件或 Visual Studio 工程文件。这样，同一套工程配置就可以在不同环境下使用，不需要为每种编译器重新编写一套完整的编译命令。

在本教程中，CMake 主要负责组织 STM32 工程的编译流程，ARM GCC 负责真正编译和链接代码，最终生成可以下载到单片机中的程序文件，例如 `.elf`、`.hex` 或 `.bin` 文件。

可以把整个过程简单理解为：

```text
CMakeLists.txt
      ↓
    CMake
      ↓
生成编译规则
      ↓
  ARM GCC 编译
      ↓
生成 STM32 程序文件
```

因此，CMake 和 ARM GCC 是两个不同的工具：CMake 负责“安排怎么编译”，ARM GCC 负责“执行具体编译”。

### 下载CMake

1. 打开 CMake 官方下载页面：

   [CMake 官方下载页面](https://cmake.org/download/)

2. 在 **Latest Release** 中找到 Windows 版本，下载 Windows 64 位安装程序，文件一般类似于：

   > cmake-4.x.x-windows-x86_64.msi

   版本号会随着 CMake 发布而变化，下载最新的稳定版本即可。

### 安装CMake

1. 双击下载的 `.msi` 安装程序。

2. 安装过程中，如果看到添加环境变量的选项，选择将 CMake 添加到当前用户或所有用户的 `PATH` 中。

   如果没有选择该选项，也可以手动把 CMake 的 `bin` 目录添加到环境变量，例如：

   > C:\Program Files\CMake\bin

3. 安装完成后，关闭已经打开的 PowerShell 或 VS Code 窗口，再重新打开终端。环境变量只会对新启动的程序自动生效。

4. 在 PowerShell 中验证安装：

   ```powershell
   cmake --version
   ```

   如果能看到 CMake 的版本号，说明 CMake 已经安装成功。

   如果终端仍然提示找不到 `cmake`，可以直接使用完整路径验证：

   ```powershell
   & "C:\Program Files\CMake\bin\cmake.exe" --version
   ```

## CMake Tools

### 什么是CMake Tools

CMake Tools 是 VS Code 的扩展，用来在 VS Code 中方便地配置、编译和管理 CMake 工程。

它可以帮助我们选择编译器、选择 Debug 或 Release 构建类型、生成构建目录、执行编译以及查看编译错误。但是，CMake Tools 本身不是 CMake，也不包含 ARM GCC，仍然需要提前安装 CMake 和 ARM GCC。

### 安装CMake Tools

1. 打开 VS Code 左侧的扩展视图，或者按下快捷键：

   ```text
   Ctrl + Shift + X
   ```

2. 搜索：

   > CMake Tools

3. 选择发布者为 **Microsoft**、扩展标识为 `ms-vscode.cmake-tools` 的扩展并安装。

   [CMake Tools 官方仓库](https://github.com/microsoft/vscode-cmake-tools)

4. 安装完成后，重新加载 VS Code 窗口。

5. 按下 `Ctrl + Shift + P` 打开命令面板，输入 `CMake`。如果能看到以下命令，说明 CMake Tools 已经安装成功：

   - `CMake: Configure`
   - `CMake: Build`
   - `CMake: Select Configure Preset`
   - `CMake: Select Kit`

### CMake Tools的图形化界面

CMake Tools 不是单独的桌面软件，它把图形化操作界面集成到了 VS Code 中。安装完成后，打开包含 `CMakeLists.txt` 的工程，VS Code 底部状态栏通常会出现 CMake 相关按钮，例如：

- 当前 Kit 或编译器；
- 当前构建类型，例如 `Debug` 或 `Release`；
- Configure 配置按钮；
- Build 编译按钮；
- 当前构建目标。

点击这些按钮，就可以完成大部分常用操作，不需要手动输入复杂的 CMake 命令。也可以使用 `Ctrl + Shift + P` 打开命令面板执行相同操作。

另外，CMake 官方还提供了一个独立的图形化程序 `cmake-gui.exe`。Windows 版 CMake 通常会同时安装它，可以在开始菜单中搜索 **CMake** 或 **CMake GUI** 打开。CMake GUI 主要用于选择源码目录、构建目录、生成器以及查看 CMake 缓存变量。

```text
CMake GUI       → 独立的 CMake 图形化程序
CMake Tools     → 集成在 VS Code 中的 CMake 图形化操作界面
```

对于本教程，推荐直接使用 CMake Tools，因为编写代码、配置工程和编译都可以在 VS Code 中完成。CMake GUI 不是必须安装的工具。

### 第一次配置CMake Tools

#### 1. 打开工程文件夹

不要只打开某一个 `.c` 文件，而是使用 VS Code 的“文件 → 打开文件夹”，打开包含 `CMakeLists.txt` 的工程根目录。

打开工程后，CMake Tools 会自动搜索 `CMakeLists.txt`，并尝试检测电脑上可用的 CMake 和编译器。

#### 2. 选择CMake路径

如果 CMake 已经加入环境变量，CMake Tools 通常会自动找到它。如果没有找到，可以在 VS Code 的 `settings.json` 中手动指定路径：

```json
{
    "cmake.cmakePath": "C:\\Program Files\\CMake\\bin\\cmake.exe"
}
```

也可以在命令面板中执行 `CMake: Configure`。如果 CMake 路径有问题，CMake Tools 会在输出面板中显示错误原因。

#### 3. 选择Kit

Kit 可以理解为一套编译器配置，通常包含编译器路径和相关工具链信息。

按下 `Ctrl + Shift + P`，依次执行：

```text
CMake: Scan for Kits
CMake: Select Kit
```

扫描完成后，从列表中选择要使用的编译器。

对于 STM32 工程，最终应当使用 ARM GCC 工具链，也就是能够找到以下程序的工具链：

```text
arm-none-eabi-gcc.exe
arm-none-eabi-g++.exe
arm-none-eabi-objcopy.exe
```

如果扫描不到 ARM GCC，不代表 ARM GCC 没有安装成功。STM32 交叉编译工程通常还需要配合工程提供的 toolchain 文件或 `CMakePresets.json` 使用，后续工程配置章节会进行说明。

#### 4. 选择构建类型

在 VS Code 底部状态栏中找到构建类型，或者通过命令面板执行：

```text
CMake: Select Variant
```

常用构建类型如下：

| 构建类型 | 说明 |
| --- | --- |
| `Debug` | 保留调试信息，方便 Orbit 进行断点和源码调试 |
| `Release` | 开启更多优化，适合发布或测试最终性能 |
| `MinSizeRel` | 尽量减小程序体积 |
| `RelWithDebInfo` | 优化程序，同时保留调试信息 |

初次配置时建议选择 `Debug`，否则生成的 ELF 文件可能缺少源码调试所需的 DWARF 信息。

#### 5. Configure配置工程

选择好 Kit 和构建类型后，执行：

```text
CMake: Configure
```

这一步会让 CMake 读取工程中的 `CMakeLists.txt`，检查编译器、头文件、库文件和构建选项，并在构建目录中生成 `CMakeCache.txt` 以及具体的编译规则。

配置成功后，通常会看到类似下面的目录：

```text
工程目录/
├─ CMakeLists.txt
└─ build/
   ├─ CMakeCache.txt
   └─ ...
```

如果 Configure 失败，应先查看 VS Code 的“查看 → 输出”面板，并在右上角选择 `CMake/Configure`，不要只看编辑器中的红色波浪线。

#### 6. Build编译工程

配置成功后，执行：

```text
CMake: Build
```

或者直接点击 VS Code 底部状态栏中的 Build 按钮。CMake Tools 会调用 CMake，再由 CMake 调用 ARM GCC 完成编译和链接。

编译输出可以在“查看 → 输出”面板中选择 `CMake/Build` 查看。编译成功后，工程通常会在 `build/Debug`、`build/Release` 或 `build` 目录中生成：

```text
*.elf
*.hex
*.bin
```

其中 `.elf` 文件包含符号和调试信息，是 Orbit 进行源码调试时最重要的文件。

### CMake Tools常用操作

| 操作 | 命令 |
| --- | --- |
| 选择编译器 | `CMake: Select Kit` |
| 扫描编译器 | `CMake: Scan for Kits` |
| 选择构建类型 | `CMake: Select Variant` |
| 配置工程 | `CMake: Configure` |
| 编译工程 | `CMake: Build` |
| 清理工程 | `CMake: Clean` |
| 删除构建缓存后重新配置 | `CMake: Delete Cache and Reconfigure` |
| 选择编译目标 | `CMake: Set Build Target` |

### CMake Tools常见问题

#### 找不到CMake

先在终端执行：

```powershell
cmake --version
```

如果终端找不到 CMake，但 CMake Tools 可以编译，可能是 CMake Tools 使用了 `cmake.cmakePath` 中指定的绝对路径，或者找到了 Visual Studio 等软件附带的 CMake。此时应在 `settings.json` 中明确指定 `cmake.exe` 的完整路径。

#### 找不到Kit

执行 `CMake: Scan for Kits`，确认 ARM GCC 的 `bin` 目录已经加入 `PATH`。如果仍然找不到，需要在 CMake 工程中配置 ARM GCC toolchain 文件或 `CMakePresets.json`，不能只依赖自动扫描。

#### 切换编译器或生成器后配置失败

CMake 会把上一次的配置保存在 `CMakeCache.txt` 中。切换编译器、生成器或 toolchain 后，执行：

```text
CMake: Delete Cache and Reconfigure
```

不要在同一个构建目录中频繁混用 CMake GUI 和 CMake Tools。如果确实切换了工具，建议删除原来的 `build` 目录后重新配置。

## Orbit

### 什么是Orbit

Orbit 是运行在 VS Code 中的 STM32 / ARM Cortex-M 嵌入式调试扩展。它可以通过 J-Link 或 CMSIS-DAP/DAPLink 连接目标单片机，并提供源码级调试、断点、单步、Watch、Timeline、RTT 日志和外部 Viewer 接入。

编译工具链和调试工具链是两套不同的工具：

```text
ARM GCC + CMake       → 编译固件，生成 ELF 文件
Orbit + 调试探针     → 下载固件并调试单片机
```

### 准备调试探针

二选一即可：

- **J-Link**：安装 SEGGER J-Link 软件包，使用 J-Link DLL 调试，并可用 `JLink.exe` 烧录；
- **CMSIS-DAP/DAPLink**：连接标准 CMSIS-DAP/DAPLink probe。1.1.0 真机验收为 v1 HID；v2 WinUSB 有代码/Mock，本版未做真机。Orbit 的 VSIX 已包含对应 helper，不需要安装 J-Link 软件，也不使用 OpenOCD/GDB server。

#### J-Link

Orbit 调试需要 SEGGER J-Link 软件包提供的驱动、`JLink_x64.dll` 和可选的 `JLink.exe`。

1. 打开 SEGGER 官方下载页面：

   [SEGGER J-Link 下载页面](https://www.segger.com/downloads/jlink/)

2. 下载并安装 Windows 版本的 J-Link Software and Documentation Pack。

3. 安装完成后，默认情况下相关文件通常位于：

   ```text
   C:\Program Files\SEGGER\JLink
   ```

4. 将 J-Link 通过 USB 连接到电脑，并确认设备驱动安装正常。

#### CMSIS-DAP / DAPLink

1. 将 probe 通过 USB 连接到 Windows，确认设备管理器能看到 CMSIS-DAP/DAPLink 接口；v2 通常使用 WinUSB，v1 使用 HID。
2. 准备与目标 MCU 匹配的 ELF/AXF；默认烧录还需要 Orbit 支持的或用户明确提供且许可可用的 Flash Algorithm。
3. 多个 probe 同时连接时，记录 serial 或 VID/PID，供 `launch.json` 精确选择。

### 安装Orbit扩展

1. 打开 Orbit 的发布页面：

   [Orbit Releases](https://github.com/zhuangyan114/Orbit/releases)

2. 下载对应版本的 `.vsix` 文件，例如：

   > Orbit-1.0.0.vsix

3. 在 VS Code 中按下 `Ctrl + Shift + P`，执行：

   > Extensions: Install from VSIX...

4. 选择刚刚下载的 `.vsix` 文件，等待安装完成，然后重新加载 VS Code 窗口。

5. 在扩展列表中搜索 `Orbit`。如果能够看到 Orbit 扩展，说明安装成功。

### 配置Orbit

安装 Orbit 后，可以按以下步骤验证调试环境：

1. 使用 CMake 和 ARM GCC 编译工程，确保生成了 `.elf` 文件。

2. 使用 J-Link 或 CMSIS-DAP/DAPLink 连接目标单片机。

3. 在 VS Code 中打开包含 `.elf` 文件的工程。

4. 创建或打开 `.vscode/launch.json`，选择 Orbit 提供的 `orbit` 调试器类型；旧配置中的 `ozone` 类型仍可用。

5. 在 launch 中选择 probe。J-Link 可省略 `probe`（默认值为 `jlink`）；CMSIS-DAP 使用：

   ```jsonc
   {
     "type": "orbit",
     "request": "launch",
     "probe": "cmsis-dap",
     "cmsisDapTransport": "auto",
     "program": "${workspaceFolder}/build/Debug/firmware.elf",
     "device": "实际 MCU 型号",
     "interface": "SWD",
     "speedKHz": 4000,
     "flashBeforeDebug": true
   }
   ```

6. 启动调试。如果能够连接目标、按配置完成或跳过烧录、加载 ELF 符号并停在源代码中，说明 Orbit、探针和固件已经正常配合工作。

当然,Orbit的 **一切配置** 都可以由ai完成,仅需在你的项目文件夹调用ai,让ai调用 `Releases\Orbit-Config-skill`
