# DAP-08 CMSIS-DAP RTT Implementation Plan

> **For agentic workers:** Execute this plan task-by-task with TDD checkpoints. Existing user changes are already staged; do not commit or restage unrelated files.

**Goal:** Implement explicit-address SEGGER RTT Up Buffer logging through the CMSIS-DAP helper and preserve structured errors, scheduler ownership, and existing J-Link behavior.

**Architecture:** Add a standalone C++ `SeggerRttReader` over an abstract byte-memory interface, then expose one helper RPC per lifecycle operation. The CMSIS-DAP TypeScript channel maps `startRtt`/`stopRtt` to control and `readRtt` to background, while `SessionTargetSelector`, `Commander`, and `DapSession` preserve result diagnostics and generation fences.

**Tech Stack:** C++17, CMake, TypeScript, Vitest, JSON-lines helper RPC, existing `NativeScheduler` and logger.

## Global Constraints

- Preserve all staged user changes and do not edit `dist/`.
- One debug session has one CMSIS-DAP physical owner; never create a second helper or J-Link fallback.
- RTT uses only target `readMemory`/`writeMemory`; no SEGGER RTT DLL API, OpenOCD, GDB server, or `JLink.exe`.
- `control > watch > timeline > background`; RTT polling is background and control pauses it.
- CMSIS-DAP uses an explicit `rttControlBlockAddress` override when provided; otherwise resolve `_SEGGER_RTT` from the loaded ELF. Never scan target RAM for the control block.
- Do not run target-mutating hardware commands without explicit authorization; do not modify `docs/bug-fix-log.md` or commit Git.
